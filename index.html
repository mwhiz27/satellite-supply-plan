    05 · Scenario controls

    Change the assumptions

    Every chart, table, and recommendation above recalculates instantly for both scenarios.

    Planned capacity timing

    "Yes" machines are guaranteed. Planned machines turn on in their listed month and count only in the + planned scenario. Shift them all to test a slip.

    Build-ahead (stockpiling)

    Off is the Excel base case: parts are made in the launch month. On locks in the base case's satellites each month, then uses spare machine hours and stock to build extra satellites, so it can only add satellites. This is the Excel's stockpiling toggle (Dashboard E3). Directional only: the build-ahead mix is a simple heuristic, and much of the stock ends up as parts that don't complete satellites, so it understates what an optimised plan could achieve.

    Satellite priority when short

    Satellite types get machine hours, and then parts, in this order. Lower rows are cut first. This changes which satellites are short and can shift the hour gaps slightly.

            06 · Method

            How the numbers are built

            1 · Demand

            Satellites launched per month × bill of materials = SKU units, needed in the launch month. Units × production hours per unit = machine hours.

            2 · Supply

            Each machine gives its supplier's days × uptime hours per month. Guaranteed counts only "Yes" machines. Guaranteed + planned also counts dated machines from their turn-on month.

            3 · Eligibility

            A machine can make a SKU only if all three hold: its supplier is qualified for the SKU, its type matches (Type C makes A, B, and C), and its size is at least the SKU's size.

            4 · Allocation (type by type)

            The same as the Excel. Each month, satellite types go in priority order. A probe pass finds how many whole satellites of that type the free hours support. A commit pass then reserves hours for exactly that many. After all five types, a fill pass gives spare hours to the remaining demand. In every pass, machines go from least to most flexible, and the hardest-to-make SKUs go first.

            5 · Satellites

            Delivered units become whole satellites in priority order. A satellite is buildable only if every SKU in its BOM is available.

            6 · Build-ahead (optional, directional)

            After the normal fill, each machine's spare hours build SKUs toward that SKU's future gap, less what's already on hand, in the same order. Each month the base case's satellites are locked in first. Stock and leftover parts then build extra satellites in priority order, so build-ahead never builds fewer satellites. It's a heuristic, so it understates the best achievable.

            Limits

            The type-by-type fill is fast and transparent but isn't a guaranteed optimum. It favours whole satellites over total hours, so the hour gap can be slightly larger than a pure hours-first fill. A solver could find better results, so treat each shortfall as an upper bound. Without build-ahead no inventory carries between months. Machines are reserved whole.
